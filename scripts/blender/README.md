# Blender pipeline (3D mode)

Everything runs headless with Blender 4.x (tested with 4.5.9 LTS), from the repo root. The export is the bicycle
add-on's (`tools/blender/bicycle_blender.py`), the same code as the Bicycle panel's Export button; placing genomes
and spawn points in Blender is described click by click in [docs/blender-entities.md](../../docs/blender-entities.md).

1. Author (or open) a .blend in `<game>/blender/`. The demo files are generated by scripts:

       blender -b --factory-startup --python scripts/blender/make_scene.py           # test/blender/meadow3d.blend
       blender -b --factory-startup --python scripts/blender/make_level.py -- plat   # plat3d/blender/plat3d.blend
       blender -b --factory-startup --python scripts/blender/make_level.py -- fps    # fps3d/blender/fps3d.blend

   Each Blender scene is one level (plat3d.blend: `courtyard` and `bonus`; a lone scene named `Scene` is the level
   `scene3d`). A scene whose "Is a level" box is off (plat3d's `models`) only holds genome models. make_level.py
   places the entities and spawn points through the add-on's Python API (`add_entity`, `add_spawn`,
   `add_path_point`), exactly what its buttons do.

2. Export (every scene):

       blender -b plat3d/blender/plat3d.blend --python scripts/blender/export.py [-- plat3d/genome]

   For each mesh object: modifiers applied, triangulated (bmesh), converted to Y up, written as
   `<object>.obj` + `.mtl` (per-corner normals and UVs, one `usemtl` group per material; diffuse color from the
   Principled BSDF's Base Color, texture from an Image Texture node linked to it). Each texture is written as a
   true-color `<image>.bimg`. Level meshes (custom property `bicycle_role` = `static`: drawn and collided, `decor`:
   drawn, `collider`: collided) get their world transform baked in and go to `genome/model/`; genome models
   (`bicycle_role = "character"`, origin at the feet, facing +X) stay in their own space and go to
   `genome/body/model/`. `genome/level/<level>.lua` lists the level's meshes (`objects`), the genomes placed in it
   (`entities`: genome, key, pos, yaw and the per-instance parameters that differ from the genome's) and its
   `spawns` (`{ x, y, z, yaw }`).

3. Build the `assets` target (part of a normal build). `bicycle-pack` reads each `.obj`, encodes it as an
   Edgebreaker-compressed `.bmesh` (see `include/data/Mesh.h`) and packs it with the textures into
   `<game>/assets.bpak`. The `.obj`/`.mtl` files are never read at runtime in a release build.

4. In the game: a scene with `world3d = { level = "courtyard" }` draws and collides the level's meshes and spawns its
   entities from their genomes (`Genome.spawn3d`); any genome with `model = "<object>"` (e.g.
   `plat3d/genome/coin.lua`) is drawn as that mesh.

## Skeletal animation

`make_scene.py` builds `pilgrim3d` as a rigged character: armature `pilgrim3d_rig` (hips, spine, head, leg_L/R,
arm_L/R), with the robe/legs/arms/head weighted to their bones, and two actions authored as keyframes in batch
mode: `walk` (24 frames) and `idle` (48 frames). `export.py` writes the mesh in its rest pose plus
`<object>.bskin`: the joint hierarchy, inverse bind matrices, each OBJ vertex's 4 strongest joints/weights
(normalised to sum 255), and per-action keyframes (translation + quaternion per joint per frame).

The packer folds the weights into the `.bmesh` (an 8th stream that follows Edgebreaker's vertex reordering) and
stores a quantized `.bskin` (16-bit translations, smallest-three quaternions, delta + zigzag varints, then deflate:
16.5 KB -> 1 KB for the pilgrim). The 3D renderer skins on the GPU (`uBones[32]`); `anim:set("walk_left")` picks the
action from the tag's prefix (`walk`, `idle`), and a walking model that stands still for ~0.3 s plays `idle`.
`BICYCLE_MODEL_ACTION=<action>` pins every rigged model to one action (screenshots).

## Not done yet

* Blending between actions (switches are immediate), more than 32 joints, and more than 4 weights per vertex.
* Per-object transforms for static objects (they're baked), vertex colors, multiple UV layers, and more than
  256 materials per mesh.
